## 1. 주장별 지지 기준과 대체 문장

### ① Mesh 바닥은 빌드에서 개미를 받치지 못했다

H0와 H1의 MeshCollider는 망가지는 방식이 달라서, 변형을 둘로 나눈다.

| 변형 | 재현하는 상태 | 근거 |
|---|---|---|
| S0a | H0식: 기본 cooking(EnableMeshCleaning 포함), Read/Write 꺼짐, 빌드 시 런타임 cooking 불필요 | `probe-H0-colliders.json` 바닥 100개 |
| S0b | H1식: EnableMeshCleaning 제거, Read/Write 꺼짐 → 런타임 cooking 필요 | `probe-H1-e2c.json` 바닥 100개, 에셋 `de8bfd48`(05-22 07:20) |
| S0′ | S0b + Read/Write 켬 | 설정만으로 해결되는지 확인 |

- 조작이 실제로 먹혔는지 확인하는 체크(통과하지 못하면 그 변형은 무효)
  - S0b 빌드 로그에 바닥 오브젝트의 MeshCollider Read/Write 오류가 있어야 한다
  - S0a와 S0′에는 같은 오류가 0이어야 한다
- 지지 기준
  - S0a 또는 S0b의 미리 정한 경로에서 지지 상실 낙하가 1건 이상 나온다
  - S3(Box)는 같은 경로에서 0건이다
- 대체 문장
  - S0′에서 낙하가 사라질 때: "에셋 임포트 설정(Read/Write 꺼짐 + cooking 옵션 변경)으로 빌드에서 Mesh 바닥이 비어 있었다. 설정에 의존하지 않는 Box를 택했다."
  - S0a·S0b 모두 낙하 0일 때: "통제 조건에서는 Mesh 바닥 낙하가 재현되지 않았다. 트랙 A의 H0 관측(repeat-01)만 근거로 쓴다."

### ② Convex는 경계를 경사면처럼 감싸 지형과 어긋났다

- 변형 S2: S0′(Read/Write 켬)과 같은 오브젝트별 MeshCollider에 convex만 켠다. 사용자가 에디터에서 했던 방식이다
- 측정: Mac 에디터 기하 감사(Windows 불필요)
  - 미리 정한 단면에서 1cm 간격으로 시각 메시 윗면과 충돌면 윗면의 높이 차이를 잰다
  - 단면은 e2 연석 횡단선 C01~C12와 S2·S3, 경계 ±60cm 범위
  - 지표: p95·최대 높이 오차, 연석 단차 소실(충돌면에서 0.1m 이상 단차가 사라진 단면 수), 255면 제한 경고
- 지지 기준: 연석 단면에서 convex 높이 오차 p95가 50mm 이상이거나, 연석 단차가 사라진 단면이 절반 이상
- 반대 기준: 연석 단면에서 convex 높이 오차 p95가 5mm 미만이면 ②는 측정으로 뒷받침되지 않는다. 그때는 "에디터에서 convex 모양을 보고 판단했다" 수준으로만 쓴다

### ③ Box 재구성은 낙하가 없고 지형과 맞는다 (+ 받침판의 한계)

- S1(받침판 한 장): 평평한 Box 한 장, 주 조건 윗면 -0.1(05-26에 사용자가 맞춘 높이). 보조로 윗면 0 기하 감사도 한다
- S3(현재 Box): 타일·도로 바닥 Box + 연석 Box. 0.02 / Discrete
- 측정
  - 기하 감사: 같은 단면에서 S1·S3의 높이 오차와 연석 단차 유무
  - 런타임: 지지 상실 낙하 수, 연석 접촉 여부
- 지지 기준
  - S1에서는 두 높이(도로 -0.1, 인도 0)를 동시에 맞출 수 없고 연석 접촉이 0이다
  - S3는 높이 오차 p95가 5mm 이하이고 연석 접촉이 있으며 낙하 0이다
- 남은 문제(남쪽 도로 0.1m 단차, 소품 관통)는 S3 결과에 그대로 함께 보고한다

### ④ 물리 설정(ContinuousDynamic, dt 0.01)은 고속 연석·벽 관통과 연석 끼임을 줄였다

**이미 있는 반대 데이터:** `Benchmarks/CurbStuckRuntimeMatrix/20261023_023059`(에디터, 현재 코드)

- Box + ContinuousDynamic: S2 끼임 6/9 (dt 0.01·0.02 모두)
- Box + Discrete: 0/9
- 빌드 측정은 아니지만, 끼임에 대해서는 주장과 반대 방향이다

설계

- Box(S3 빌드)에서 dt {0.02, 0.01} × 충돌 검사 {Discrete, ContinuousDynamic}의 2×2를 돌린다. 실행 옵션 `-benchDt`/`-benchCcd`로 바꾸므로 재빌드하지 않는다
- 연석 돌진 case: S2 road_009·S3 road_019(+ C 횡단선 연석 중 2곳), 속도 Sprint·Boost·Boost+Sprint, 좌우 오프셋 -2/0/+2cm
- 지표 두 개
  - 관통: 벽면을 지나간 수(`passed_curb`)
  - 끼임: 후진·좌우·점프 탈출 실패 수
- 지지 기준: ContinuousDynamic 또는 dt 0.01에서 관통이 Discrete·0.02보다 줄어든다(같은 case 대응)
- 대체 문장(결과에 따라)
  - 관통은 줄고 끼임은 늘 때: "CCD는 고속 관통을 줄였지만 연석 끼임을 늘렸고, 끼임은 접촉 법선 처리 코드(H5)로 대응했다." (트레이드오프)
  - 관통 차이가 없을 때: "통제 조건에서 물리 설정의 관통 개선은 확인되지 않았다." ④는 포트폴리오에서 뺀다

## 2. 공통 실행 규칙

- **작업 공간·하네스 일치**
  - H7 작업 공간을 APFS 복제(`cp -c`)한 공간 하나에서 하네스를 최신으로 한 번 동기화한다
  - 그 공간에서 S0a·S0b·S0′·S1·S2·S3(무수정 H7)를 순서대로 바꿔 가며 빌드한다
  - 모든 변형이 같은 runner 판을 쓴다. 변형별 patch diff와 SHA를 기록한다
- **시작 높이**
  - 변형마다 충돌면 높이가 다르므로, 각 case는 충돌면 윗면 probe(변형별) 위 0.05m에서 시작해 정착시킨다
  - `initialPenDepth` > 5mm인 trial은 이 트랙에서 무효다
- **판정 revision (thresholds-B1, 새로 동결)**
  - 지지 상실 낙하: 시각 지면보다 0.5m 이상 하강
  - 시각면 불일치: 정지 높이와 시각 지면의 차이(mm). 연속값으로 보고하고 fall과 구분한다
  - 나머지는 thresholds-r4를 따른다
- **case 집합(예정)**
  - 바닥: e2의 C(24)·L(6)·S(14)·M(2) 경로를 H7 좌표 그대로 쓰고, 시작 높이만 위 규칙으로 바꾼다
  - 연석: ④의 연석 돌진 세트
  - 판정 검증 CK 4개
- **반복**: 변형별 case당 3회(seed 1·1·2). ④의 2×2는 case당 3회
- **확인 순서**: 변형마다 Mac smoke를 짧게 돌려 조작 체크와 시작 침투 0을 확인한 뒤 Windows로 보낸다. Mac 결과는 Windows 결과로 쓰지 않는다
- **PC별 분리 집계.** 정식(M6 이후)이 아니라 M5 통제 탐색으로 표기한다
