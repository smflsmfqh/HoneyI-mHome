# 개미 플레이어 충돌 검증 — 포트폴리오 근거(M11)

작성: 2026-11-10. 근거: M6-r1(48 run)·M9 감사·M10-r1(6 run). 모든 수치는 아래 출처 파일에서 그대로 옮겼다. 판정 규칙은 결과를 보기 전에 freeze로 고정했다.

## 2. 주장별 문장

### ① Mesh Collider 바닥 낙하

> Mesh Collider 바닥은 빌드에서 개미를 받치지 못했다. E2_C 이동 경로 24조건 중 당시 설정(H0식) 14, cooking 옵션을 바꾼 설정(H1식) 24에서 개미가 바닥 아래로 떨어졌다. H1식에 Read/Write를 켜도 14로, 설정만으로는 해결되지 않았다. 실제 당시 버전 빌드에서도 6조건(조건별 4/6~6/6회)에서 낙하가 재현됐다.

- 낙하 원인이 두 가지다. H1식은 시작 직후 바로 떨어지고(중앙 0.34초, 바닥 콜라이더가 비어 있음), H0식은 이동 중 주로 점프 착지에서 떨어진다(42건 중 36건). 하나의 원인처럼 쓰지 않는다.
- dt 0.02·Discrete에서만 측정했다.

### ② Convex Mesh 대안을 채택하지 않은 이유

> Convex Mesh Collider는 연석 경계를 경사면처럼 감싸 지형과 어긋났다(연석 구간 높이 오차 p95 200mm, 단차 90곳 모두 소실). 런타임에서도 낙하가 남았다(4/24조건).

### ③ Box 재구성 바닥(현재 구조)

> Box로 다시 만든 바닥에서는 같은 경로 24조건 모두 낙하가 없었다(원본 게임 설정에서도 0). 단차는 90곳 중 84곳을 보존했다.

- **쓰지 않는다:** "지형과 정확히 맞는다". 연석 구간 높이 오차 p95가 100mm로, 사전 기준 5mm를 넘었다. 원인은 남쪽 도로(`road_009_floor`)의 0.1m 단차다. 오차 지점의 94%와 단차 소실 6곳이 모두 이 도로에 있다. 기록상 판정은 '지지 아님(런타임 조건만 충족)'이다.

### ④ 물리 설정(dt·CCD)만으로는 부족했다

> 고정 시간 간격을 0.01초로 줄이고 ContinuousDynamic을 켜니 고속 연석 실패 조건이 24/34에서 13/34로 줄었지만 없어지지는 않았다(13 중 6은 끼임). 대신 부작용이 생겼다. 0.02초에서는 관통하던 정면 돌진 6조건이 연석 안에 완전히 갇히는 끼임으로 바뀌었다. 그래서 설정이 아니라 콜라이더 구조를 고쳤다(⑤).

- trial 수: 관통 72/102 → 19/102, 끼임 0/102 → 18/102. 각각만 바꾸면 dt만 38/102, CCD만 48/102.
- **쓰지 않는다:** M6 해석 원문의 "남은 관통과 끼임은 ⑤로 해결했다". ④는 원본 씬에서, ⑤는 기본 설정 0.01/CCD에서 측정해 조건이 다르다. "부작용을 찾았고 구조로 고쳤다"로 쓴다.
- 끼임이 생기는 원인은 수치로만 보고한다(원인 미확인).

### ⑤ 연석 BoxCollider 밑면 연장 (적용됨, 커밋 `6c26d2a`)

> 연석 BoxCollider 820개의 밑면을 도로면 아래(-0.3m)까지 늘렸다. 설계에 쓴 연석 2지점의 고속 돌진 34조건에서 관통·끼임 조건이 13에서 0이 됐다(trial: 관통 21·끼임 18 → 0·0/102). NPC·차량을 켠 게임 조건에서도 같았다(관통 20·끼임 18 → 0·0). 수정 전후 같은 조건을 1:1로 비교한 174쌍에서 악화는 0건이었다.
>
> 설계에 쓰지 않은 연석 8지점에서도 다시 확인했다(80조건). 직선·곡선 연석 6지점에서는 실패 조건이 7에서 0이 됐다. 그러나 두 연석 박스가 맞닿는 접합부 2지점에서는 수정 전후 모두 10/20으로 같았다. 결론적으로 실패 조건을 줄였지만 없애지는 못했다(19/79 → 10/76, 두 빌드 공통 조건 기준 17/76 → 10/76).

- 함께 쓴다: 충돌 직후 연석에 최대 3.3cm 파고들었다가 밀려난다(10지점 기준. 설계 2지점만 보면 2.6cm). 사용자 플레이에서도 보였고, 모두 첫 후진에서 빠져나왔다.
- 접합부 설명은 **가설**로만 쓴다. 실패는 이음매를 정확히 겨눈 진입에서만 나왔고, 2cm 옆으로 비키면 통과하지 않았다. 이음매에서는 가장 가까운 면이 박스 끝면이라 침투 해소가 옆 박스 쪽으로 밀어 이음매를 따라 들어간 것으로 보인다. 밑면 연장과는 다른 기전이라 결과가 같았다. 개미는 갇히지 않고 모두 후진으로 빠져나왔다.
- 면 범위 밖으로 분류한 trial(접점이 짧은 곡선 연석 면의 끝을 지난 경우)은 실패로 세지 않았다. 조건 ID는 해석 파일에 있다. 진단해 보니 수정 후 실패를 숨긴 경우는 없었고, 오히려 수정 전 끼임 1조건이 가려졌다.
- **쓰지 않는다:** "맵 전체 연석에 일반화됐다", "연석 문제를 해결했다", "접합부 원인을 확인했다".

### 면접용 한 문단

> 개미가 지름 2cm 캡슐이라 고속으로 연석에 부딪히면 관통하거나 끼였습니다. 먼저 dt와 CCD를 바꿔 봤는데, 관통은 줄었지만 정면 돌진이 아예 갇히는 끼임이 새로 생겼습니다. 원인은 연석 박스 밑면이 도로면에 딱 붙어 있어 침투를 풀 때 아래로 밀리는 데 있다고 보고, 밑면을 도로 아래까지 늘렸습니다. 측정한 2지점에서 34조건 중 13조건이던 실패가 0이 됐고, 악화는 없었습니다. 설계에 쓰지 않은 8지점에서 다시 확인하니 직선·곡선은 해결됐지만 박스 두 개가 맞닿는 접합부는 그대로였습니다. 거기는 다른 기전으로 보고 있습니다. 판정 규칙은 모두 결과를 보기 전에 고정했습니다.

## 5. 재실행 방법

1. Windows PC에서 `Builds/M6-r1-A.zip`·`M6-r1-B.zip`·`M10-r1.zip`을 풀고 `RunM6A.cmd`(약 2시간 50분)·`RunM6B.cmd`(약 1시간 10분)·`RunM10.cmd`(약 1시간)를 실행한다. 창을 최소화하지 말고 실행 중 입력을 하지 않는다.
2. 결과 ZIP을 `Evidence/`에 넣고 run마다 `python3 -I Harness/Tools/analyze_physics_bench.py <run> --thresholds Harness/Cases/thresholds-B1.json --out Evidence/<M6|M10>/analysis/<run>-a1`을 실행한다.
3. 집계: `python3 -I Tools/summarize_M6.py …`, `python3 -I Tools/summarize_M10.py "$PWD" <out.json>`(루트는 절대 경로). 감사: `Tools/audit_M9.py`.
4. 빌드 자체를 다시 만들려면 `Tools/build_m6.sh`(복제 프로젝트 `Benchmarks/.physics-work/project-H7B`). 씬 SHA는 BASE `9d0bb583…`, CURBFIX `12ba8273…`이어야 한다.

제한: 빌드 ZIP과 원시 결과는 Git에 들어 있지 않다(로컬 `Benchmarks/` 미추적). 다른 기기에서 재검증하려면 이 폴더를 따로 옮겨야 한다.
